# Performance and missing originals

Authorized scope: large-battle calculation, metadata/catalog performance, and
missing-file finder. No saved filter presets, set merge/split, clothing-color
detection, browser-access troubleshooting, or artwork changes.

Versions: standalone 2.9.24, runtime 2.7.74, Workbench 2.0.20. The NovelAI
userscript payload remains 2.8.101; it uses the updated companion.

The bounded sparse covariance solver preserves rating means and uncertainty
semantics, with per-column squared residual tolerance 1e-18. A seeded synthetic
2,050-entry / 16,400-vote fit fell from 95.07 s to 6.38 s. An independent dense
matrix inversion at 2,050 entries verifies the new inverse diagonal. Existing
small-board, disconnected, tie and repeated-vote tests remain required.

At 30,000 metadata records / 750 sets, median favorite-change time fell from
1.080 s to 0.074 s, and duplicate catalog preparation from 5.940 s to 0.851 s.
Measurements are Linux synthetic fixtures, not promises for a particular
Windows collection. Reproduce with `tools/benchmark-workflows.py` and
`tools/benchmark-library.py`.

Missing file finder is available in library Project tools and the Folder
Organizer's Missing files button. It checks recorded originals, searches only
folders the user enters, and matches SHA-256 checksums. Recovery copies selected
verified files back to their expected locations; it does not move source files,
overwrite existing files, or change set membership or source identities. This
is recovery into existing paths, not a general folder relocation wizard.
Scans can be stopped and reports downloaded. Restored Workbench originals are
usable after restart despite new filesystem timestamps/inodes.

Validation includes full runtime and Workbench suites, DOM interaction checks,
364 native production-card renders, release-pipeline regression tests, failed
atomic-write rollback, checksum mismatches, occupied destinations, stale scans,
cancellation, and persistence of recovered Workbench references. Browser layout
and installation on the user's Windows machine remain unverified.

Publish source only through the GitHub workflow. The release receipt must show
`published_verified` after manifest routes and downloadable bytes match.
